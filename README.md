# LuckyEngine Scripting Docs

The documentation site for the **LuckyEngine C# scripting API** — concept guides plus a
full API reference generated directly from the engine's `Hazel-ScriptCore` source.

- **Theme:** [Material for MkDocs](https://squidfunk.github.io/mkdocs-material/)
- **Versioning:** [mike](https://github.com/jimporter/mike) — a version dropdown lets readers switch between engine releases (e.g. `2026.1` ↔ `2026.2`)
- **API reference:** generated by a small Roslyn-based tool (`tools/ApiDocGen`) that turns C# + `///` doc comments into Markdown

This is a **standalone repository**. It reads the engine's C# source from a separate
LuckyEngine checkout (configurable path / submodule / CI checkout); nothing here depends
on being inside the engine tree.

## How it works

```
LuckyEngine/Hazel-ScriptCore/Source/**.cs
        │
        │  tools/ApiDocGen  (Roslyn: parse public API + XML doc comments)
        ▼
docs/api/**.md            ← generated (gitignored)
docs/**.md                ← hand-written guides (committed)
        │
        │  mkdocs build  (Material theme)
        ▼
site/                     ← static HTML
        │
        │  mike deploy <version>
        ▼
gh-pages branch           ← versioned, with a version-selector dropdown
```

The reference is **never hand-edited** — it's a build artifact. To change reference text,
edit the `///` XML doc comment on the type/member in the engine source; the next build
picks it up. The hand-written guides under `docs/getting-started/` and `docs/guides/` are
the parts you author directly.

## Quick start (local preview)

```powershell
# 1. One-time: create the Python environment
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# 2. Point the generator at your engine checkout (one of):
#    - pass -Source each time (below), or
#    - set an env var:      $env:LUCKYENGINE_SCRIPTCORE = "C:\Dev\LuckyRobots\LuckyEngine\Hazel-ScriptCore\Source"
#    - or create tools/ApiDocGen/apidocgen.local.json (see below)

# 3. Generate the API reference and serve with live reload:
.\scripts\serve.ps1 -Source C:\Dev\LuckyRobots\LuckyEngine\Hazel-ScriptCore\Source
```

Then open <http://127.0.0.1:8000>. Editing a guide hot-reloads; re-run
`.\scripts\generate.ps1` after changing engine source to refresh the reference.

> The version dropdown only appears in **mike** builds (see below), not in plain
> `mkdocs serve`.

## The generator (`tools/ApiDocGen`)

A .NET 9 console tool that parses the `.cs` files **syntactically** (no engine build or
dependency resolution required) and emits one Markdown page per public type, grouped into
categories, with cross-references resolved to relative links.

Run it directly:

```powershell
dotnet run --project tools/ApiDocGen -c Release -- --root . --source <Hazel-ScriptCore\Source>
```

**Source path resolution order:** `--source` → `$LUCKYENGINE_SCRIPTCORE` →
`sourceRootCandidates` in `apidocgen.config.json`.

**Scope** is controlled by `apidocgen.config.json`:

- `excludeNamespaces` / `excludeFileGlobs` / `excludeTypeNamePatterns` — keep internal
  plumbing (gRPC, interop, generated code) out of the user-facing docs.
- `categories` — maps source folders (and `Component`-derived types) to the sections you
  see in the nav. Currently covers Scene, Components, Math, Physics, Rendering, Audio,
  Animation, Core & Input, Editor Attributes, and Robots & Learning (MDP).

For a machine-local source path that isn't committed, create
`tools/ApiDocGen/apidocgen.local.json` (gitignored):

```json
{ "sourceRootCandidates": ["C:/Dev/LuckyRobots/LuckyEngine/Hazel-ScriptCore/Source"] }
```

### Using a git submodule instead

If you prefer a reproducible, self-contained checkout, add the engine as a submodule at
`./engine` (the first candidate in `apidocgen.config.json` already points there):

```bash
git submodule add https://github.com/luckyrobots/LuckyEngine engine
```

## Versioning with mike

Each engine release is published as its own immutable version; readers switch via the
header dropdown. mike stores every version as built HTML on the `gh-pages` branch.

```powershell
# Publish the current release locally (for review) as 2026.1 + "latest":
.\scripts\deploy-version.ps1 -Version 2026.1 -Latest

# Preview all published versions with the switcher:
.venv\Scripts\mike serve

# When 2026.2 ships, publish it and push it live as the new latest:
.\scripts\deploy-version.ps1 -Version 2026.2 -Latest -Push
```

Under the hood that runs `mike deploy --update-aliases <version> [latest]` and
`mike set-default latest`. Old versions remain available in the dropdown and are never
overwritten.

## Continuous integration

`.github/workflows/docs.yml`:

- **push / PR to `main`** → checks out the engine, generates the reference, and runs
  `mkdocs build --strict` (fails on any broken link or anchor). No deploy.
- **manual "Run workflow"** → additionally publishes a version with mike (inputs:
  `version`, `alias`, `engine_ref`) and pushes `gh-pages`.

If LuckyEngine is private, add a read-scoped PAT as the `ENGINE_REPO_TOKEN` secret.

## Hosting

mike publishes to the `gh-pages` branch. Enable **GitHub Pages → Deploy from branch →
`gh-pages`** on this repo (or point any static host at that branch). Then set `site_url`
in `mkdocs.yml` to the published URL.
