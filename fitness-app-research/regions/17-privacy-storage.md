# privacy-storage

## Key findings
- Free-provisioning capability matrix (verified from raw HTML of Apple's 'Supported capabilities (iOS)' table): the free 'Apple Developer' (personal team) column HAS checkmarks for HealthKit, App Groups, Background Modes, Data Protection, Keychain Sharing, Maps, HomeKit, Inter-App Audio, and Wireless Accessory Configuration — so the core of this app (HealthKit + background modes) is fully buildable on a free account.
- Free personal teams do NOT get: iCloud (CloudKit, iCloud Documents, iCloud key-value storage), Push Notifications, Sign in with Apple, WeatherKit, In-App Purchase, Game Center, Associated Domains, App Attest, or HealthKit Estimate Recalibration. Any sync/backup design must avoid iCloud entitlements entirely.
- HealthKit read-permission denial is invisible by design — Apple docs state verbatim: 'To help prevent possible leaks of sensitive health information, your app cannot determine whether or not a user has granted permission to read data. If you are not given permission, it simply appears as if there is no data of the requested type in the HealthKit store.' authorizationStatus(for:) reflects ONLY sharing (write) permission.
- HealthKit is the durable, system-level store: 'The user's device stores all HealthKit data locally' (Apple docs); the HealthKit database lives outside the app sandbox, survives app deletion/reinstall, and merges data from multiple sources (Apple Watch, iPhone, other apps). Workouts, routes (HKWorkoutRoute as CLLocation arrays), sleep, and dietary samples written there are all readable again after any reinstall.
- The HealthKit store is encrypted while the device is locked: apps may not be able to READ from the store in the background when locked, but can still WRITE (HealthKit caches writes and commits on unlock). This constrains background processing design.
- New API (found in current Apple docs): users can now grant a LIMITED TIME WINDOW of read history in the authorization prompt; HKHealthStore.getEarliestAuthorizedSampleDate(for:completion:) returns per-type earliest readable dates. The app still cannot distinguish 'denied' from 'full access' — limited access is the only detectable state, by design. For a personal app the user will just grant full history, but queries should tolerate this.
- HKHealthStore.earliestPermittedSampleDate() is a systemwide platform floor — saving samples earlier than it fails with errorInvalidArgument and queries clamp to it; relevant if re-importing old exported data back into HealthKit.
- App container persistence across weekly re-signs: deploying a new build from Xcode with the SAME bundle ID installs as an upgrade — Documents/, Library/ (including UserDefaults in Library/Preferences and any SwiftData/SQLite store in Application Support) are preserved. When the 7-day free provisioning profile expires the app merely refuses to LAUNCH ('Unable to Verify App'); the container is NOT deleted, and re-running from Xcode restores launchability with data intact. Data is only lost if the user deletes the app from the home screen or the bundle ID changes. (7-day expiry and upgrade-install behavior are universal community consensus; Apple does not document the 7-day figure on a fetchable page.)
- Apple's File System Programming Guide confirms Documents/ and Library/ (except Caches) are backed up by device backup (iCloud/Finder backup) with no entitlement needed — but for a sideloaded app a device-backup RESTORE cannot reinstall the app from the App Store, so restored container data is effectively unrecoverable; do not rely on device backup as the backup strategy.
- Export to iCloud Drive WITHOUT the iCloud entitlement is fully supported: UIDocumentPickerViewController 'provides access to documents or destinations outside your app's sandbox' — the picker (and SwiftUI .fileExporter / share sheet) runs out-of-process and can save files into iCloud Drive or On My iPhone with zero entitlements. This is the sanctioned backup channel for a free-provisioned app.
- Zero-entitlement alternative surfaces for backup: setting UIFileSharingEnabled + LSSupportsOpeningDocumentsInPlace in Info.plist exposes the app's Documents folder directly in the Files app (and Finder file sharing), letting the user copy the app's database/JSON out manually; Keychain items also persist across app deletion in practice (undocumented behavior — fine for a tiny XP/streak blob, not for primary data).
- Reinstall resync pattern verified: HKAnchoredObjectQuery returns an HKQueryAnchor identifying all samples previously seen; persist the archived anchor in the app container. After a reinstall wipes the container, pass a nil anchor and the query returns a full snapshot of all historical HealthKit data plus continuous updates — i.e., the entire workout/sleep/nutrition history rebuilds itself from HealthKit automatically.
- Background delivery of HealthKit updates requires the com.apple.developer.healthkit.background-delivery entitlement (iOS 15+), which is part of the HealthKit capability available to free teams; enableBackgroundDelivery(for:frequency:) wakes the app at most at the given frequency, stepCount is capped at hourly, and HealthKit stops delivering after 3 unacknowledged deliveries (must call the completion handler). Not supported in Simulator.
- Local storage options: SwiftData (Apple, macro-based on Core Data, @Model + @Query SwiftUI integration, no external deps — its optional multi-device sync requires CloudKit so is unavailable here) vs GRDB.swift v7.11.1 (actively maintained SQLite toolkit, iOS 13+, Swift 6.1, SQL generation + database observation + robust concurrency, ValueObservation pairs well with SwiftUI). For a single-user app with HealthKit as the system of record, either works; app-only state is small.
- Export formats: official Garmin FIT Swift SDK exists (github.com/garmin/fit-swift-sdk, SPM package 'FITSwiftSDK', iOS 14+, Swift 6 tools, includes ActivityEncodeTests showing how to ENCODE Activity FIT files); community alternative roznet/FitFileParser (41 stars) for parsing. GPX 1.1 is trivial XML (trk/trkseg/trkpt with lat/lon/ele/time; heart rate via Garmin TrackPointExtension gpxtpx:hr) generated from HKWorkoutRoute CLLocations; CSV is trivial. Strava accepts FIT/TCX/GPX (+.gz) uploads if ever needed.
- HealthKit privacy usage rules (relevant even off-App-Store as design guidance): apps must include NSHealthShareUsageDescription (read) and NSHealthUpdateUsageDescription (write) Info.plist keys or they CRASH on the authorization request; HealthKit data may not be used for advertising and requires fine-grained per-type permission grants.
- HKWorkoutRoute stores GPS as CLLocation arrays attached to workouts; build with HKWorkoutRouteBuilder, read back in batches with HKWorkoutRouteQuery — so Strava-style route maps need no separate GPS database; the Apple Watch Ultra 3's native Workout app already writes routes to HealthKit that the iPhone app can read.
- Characteristic data (birthdate, biological sex, blood type) is read-only to apps — the user must enter it in the Health app; apps can never save characteristics.

## Specifics
- Free personal team capability checkmarks (exact): App groups YES, Background modes YES, Data protection YES, HealthKit YES, HomeKit YES, Inter-App Audio YES, Keychain sharing YES, Maps YES, Wireless Accessory Configuration YES; NO for: iCloud CloudKit / iCloud documents / iCloud KV storage, Push notifications, Sign in with Apple, Apple Pay, Game Center, In-App Purchase, WeatherKit, Associated domains, App Attest, NFC, Network extensions, Personal VPN, Siri, Wallet, HealthKit Estimate Recalibration
- MapKit note from same Apple page: free accounts can use MapKit but cannot provide routing directions
- HKHealthStore.authorizationStatus(for:) -> HKAuthorizationStatus — sharing (write) status only; .sharingAuthorized with no read permission means the app sees only data it wrote itself
- HKHealthStore.getRequestStatusForAuthorization(toShare:read:) -> HKAuthorizationRequestStatus — tells whether the permission sheet WOULD be shown (i.e., whether you already asked), without revealing grant/deny
- HKHealthStore.getEarliestAuthorizedSampleDate(for: Set<HKObjectType>) -> [HKObjectType: Date] — per-type earliest readable date when user granted limited history; empty dict = no type is time-limited
- HKHealthStore.earliestPermittedSampleDate() -> Date — systemwide floor; saves before it fail with HKError.errorInvalidArgument
- Info.plist keys: NSHealthShareUsageDescription (read), NSHealthUpdateUsageDescription (write) — missing key = crash at requestAuthorization
- Entitlements: com.apple.developer.healthkit (free-team OK); com.apple.developer.healthkit.background-delivery required for enableBackgroundDelivery on iOS 15+ (fails with hkErrorAuthorizationDenied without it)
- enableBackgroundDelivery(for:frequency:) — HKUpdateFrequency .immediate/.hourly/.daily/.weekly; stepCount max hourly on iOS; watchOS budget: 4 wakes/hour shared with WKApplicationRefreshBackgroundTask when a complication is on the active face; 3 missed completion handlers = deliveries stop; HKCharacteristicType not supported
- HKAnchoredObjectQuery: pass anchor=nil for full-history snapshot + updateHandler for live changes; HKQueryAnchor conforms to NSSecureCoding — persist via NSKeyedArchiver data in UserDefaults; also reports HKDeletedObject UUIDs so local caches can mirror deletions
- HealthKit store encryption: device encrypts HealthKit store when locked; reads may fail in background while locked; writes are cached and committed on unlock
- Delete/reinstall semantics: Xcode build-and-run over same bundle ID = upgrade install, container preserved (Documents/, Library/Application Support/, Library/Preferences aka UserDefaults); home-screen delete = container wiped but HealthKit data and Health-app permission records survive; 7-day profile expiry blocks launch only
- Free account operational limits (community-reported, not on a fetchable Apple page): profiles valid 7 days; ~10 App IDs per 7 days per free account; up to 3 apps installed concurrently via free provisioning
- File System Programming Guide: Documents/ and Library/ backed up by iTunes/iCloud device backup; Library/Caches and tmp/ not backed up; NSURLIsExcludedFromBackupKey to exclude files; sideloaded apps can't be restored from device backup because the store can't reinstall them
- UIDocumentPickerViewController(forExporting:) moves/copies files to any destination incl. iCloud Drive with no entitlement (out-of-process picker grants sandbox exception via security-scoped URLs; startAccessingSecurityScopedResource / bookmarkData(options: .withSecurityScope) for persistent access)
- SwiftUI equivalents: .fileExporter(isPresented:document:contentType:defaultFilename:onCompletion:) and .fileImporter — same zero-entitlement mechanism; UIActivityViewController/ShareLink for share-sheet export
- Info.plist pair UIFileSharingEnabled=YES + LSSupportsOpeningDocumentsInPlace=YES exposes app Documents folder in Files app ('On My iPhone') for drag-out backup
- SwiftData: @Model macro, @Attribute/@Relationship, ModelContainer/ModelContext, @Query in SwiftUI; built on Core Data; default store in Application Support; CloudKit sync optional and unavailable on free provisioning
- GRDB.swift: v7.11.1 (June 2026), iOS 13+/Swift 6.1/SQLite 3.20+, features SQL generation, ValueObservation database observation, WAL-mode concurrency (DatabasePool), migrations; repo github.com/groue/GRDB.swift
- Official Garmin FIT Swift SDK: github.com/garmin/fit-swift-sdk, SPM URL https://github.com/garmin/fit-swift-sdk.git, module FITSwiftSDK, iOS 14+/macOS 12+, Swift Tools 6.0; ActivityEncodeTests.swift demonstrates encoding Activity FIT files; docs at developer.garmin.com/fit
- Community FIT parser: roznet/FitFileParser (Swift package wrapping FIT parsing, 41 stars, updated 2026)
- GPX 1.1 route export shape: <trk><trkseg><trkpt lat= lon=><ele><time> with <extensions><gpxtpx:TrackPointExtension><gpxtpx:hr> for heart rate; source data = HKWorkoutRouteQuery batches of CLLocation (coordinate, altitude, timestamp, horizontalAccuracy)
- Strava upload API accepts data_type: fit, fit.gz, tcx, tcx.gz, gpx, gpx.gz (developers.strava.com/docs/uploads — page itself blocked from fetch, format list is stable public knowledge)
- HKWorkoutRoute workflow: HKWorkoutRouteBuilder.insertRouteData(_:) during workout -> finishRoute(with:metadata:) -> route sample linked to HKWorkout; read via HKWorkoutRouteQuery (batched, async)
- HealthKit object model: HKObject UUID + metadata (custom keys allowed — usable to tag app-written samples, e.g. XP-relevant workouts) + HKSourceRevision + HKDevice; all samples immutable; deletions surfaced as HKDeletedObject
- Characteristic types (birthdate, sex, blood type, skin type) are app-read-only; user edits only in Health app
- isHealthDataAvailable() must be checked (false on iPad pre-iPadOS 17-ish/mac); errorHealthDataRestricted in enterprise-restricted environments
- Keychain data persists across app uninstall/reinstall in practice (undocumented, was briefly changed in iOS 10.3 beta then reverted) — viable for a tiny avatar-level/streak blob as belt-and-suspenders
- Observer/background queries don't work on Simulator — test HealthKit background paths on device
- HealthKit iCloud sync of Health data is a user-level OS feature (Settings > iCloud > Health, end-to-end encrypted with two-factor auth) and happens independent of the app with no entitlement — Apple support pages confirming details (support.apple.com/102308, platform security guide) were 403-blocked from this session, so treat E2E specifics as high-confidence but not re-verified here

## Recommendations
- Make HealthKit the system of record for everything it can model: workouts (+HKWorkoutRoute GPS), sleep, body mass, dietary energy/macros (dietary* quantity types), heart rate, HRV. It survives app deletion, weekly re-signs, and phone restores (user's own iCloud Health sync), so the app's history is automatically rebuilt after any reinstall via HKAnchoredObjectQuery with a nil anchor.
- Keep only app-native state outside HealthKit — XP/level, avatar, streaks, quests, custom food library, settings — in a small local store. SwiftData is sufficient and lowest-friction for this size; choose GRDB only if you want SQL/ValueObservation control. Since HealthKit holds the heavy data, the app DB stays tiny, which makes JSON snapshot backup trivial.
- Backup strategy for the sideloaded reality: (1) rely on container persistence across Xcode re-deploys (same bundle ID, never delete the app); (2) add an explicit 'Export backup' button that writes a single JSON snapshot of app-native state via .fileExporter into iCloud Drive (no entitlement needed) — plus optional auto-snapshot to Documents/ with UIFileSharingEnabled so it's always visible in Files; (3) on fresh install, offer 'Import backup' via .fileImporter and then resync all health history from HealthKit. Do NOT design around iCloud device backup (restore can't reinstall a sideloaded app) or any iCloud entitlement (unavailable on free team).
- Store the archived HKQueryAnchor per data type in the app container; on first launch (or anchor missing after reinstall) run full-history anchored queries and recompute derived stats/XP deterministically from HealthKit data, so gamification state can be mostly reconstructed even without a JSON backup — design XP formulas to be replayable from history.
- Never branch UI on read-permission state: authorizationStatus only reflects write permission, denied reads just look like empty data. Use getRequestStatusForAuthorization to decide whether to show the permission sheet, and getEarliestAuthorizedSampleDate to clamp query ranges if history access is limited.
- Include NSHealthShareUsageDescription and NSHealthUpdateUsageDescription from day one (missing = crash at requestAuthorization), enable the HealthKit + background-delivery entitlements (both work on free personal team), and expect background reads to fail while the phone is locked — queue work for unlock/foreground.
- For GPX export (Strava-like sharing), generate GPX 1.1 with gpxtpx:hr heart-rate extensions from HKWorkoutRouteQuery + heart-rate samples — pure string templating, no library. If FIT export is wanted, use the official Garmin fit-swift-sdk SPM package (encodes Activity files, iOS 14+). Offer CSV for tabular dumps. All three exit through the same entitlement-free fileExporter/share-sheet path.
- Weekly re-sign workflow tip: keep the bundle ID permanently fixed and re-deploy from Xcode BEFORE the 7-day profile lapses (expiry only blocks launch, data survives — but avoid the temptation to delete/reinstall, which wipes the container and the query anchors, though never the HealthKit history).
