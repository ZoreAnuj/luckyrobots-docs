# maps-gps

## Key findings
- Reading Watch GPS routes is a two-step HealthKit query: first fetch HKWorkoutRoute samples for a workout via HKAnchoredObjectQuery/HKSampleQuery on HKSeriesType.workoutRoute() with HKQuery.predicateForObjects(from: workout), then run HKWorkoutRouteQuery(route:) which streams CLLocation arrays in batches (~100 points) through a callback with a 'done' flag; wrap it in withCheckedThrowingContinuation or AsyncThrowingStream for async/await. A single workout can contain MULTIPLE HKWorkoutRoute samples (segments) — apps that assume one route crash (documented pilif/GpxExport issue #1), so iterate all route samples.
- Each CLLocation from a workout route carries coordinate, timestamp, altitude (barometer-fused on Apple Watch), speed, course, horizontalAccuracy and verticalAccuracy at roughly 1 Hz, already smoothed by watchOS — so pace, elevation profile, and per-point coloring can all be derived from the route alone without extra queries; however HKWorkout's own distance statistic can differ from route-summed distance, so display the HealthKit statistic as canonical distance and use the route only for geometry.
- iOS 17+ SwiftUI MapKit renders routes natively: Map { MapPolyline(coordinates:) or MapPolyline(mkPolyline) } with .stroke(Gradient(colors:[...]), style: StrokeStyle(lineWidth:, lineCap:.round, lineJoin:.round)) draws a gradient that follows the line path — but gradient stops are distributed evenly along the line, not data-driven.
- For true pace/HR-colored polylines the correct API is MKGradientPolylineRenderer (iOS 13+, UIKit MKMapView wrapped in UIViewRepresentable): renderer.setColors(_:locations:) takes UIColors plus unit-distance fractions (0...1 along the polyline), so you compute each point's cumulative-distance fraction and map its pace or HR zone to a color. The pure-SwiftUI fallback is splitting the route into many short solid-colored MapPolyline segments (used by apps like RunnersHeart, which colors by HR zone with direction arrows), which performs acceptably up to a few thousand segments.
- Route thumbnails (Strava-feed style) are built with MKMapSnapshotter: configure MKMapSnapshotter.Options (region/mapRect from polyline.boundingMapRect with padding, size, traitCollection for dark/light, pointOfInterestFilter = .excludingAll), take the snapshot, then draw the route on snapshot.image with UIGraphicsImageRenderer using snapshot.point(for: coordinate) to project each GPS point; cache resulting PNGs keyed by workout UUID because both the HealthKit route query and the snapshot are slow.
- Elevation gain must be computed with smoothing + hysteresis, not naive summing: Strava's published method uses a ~2 m threshold for barometric data and ~10 m for GPS-only before counting a climb; the standard pattern is moving-average (or Kalman) smoothing of CLLocation.altitude then only accumulating ascent once cumulative rise exceeds the threshold. Apple Watch workouts also store HKMetadataKeyElevationAscended metadata you can read directly as a cross-check.
- Personal all-time heatmaps in MapKit are best done with one custom MKOverlay/MKOverlayRenderer that draws every stored polyline (or many low-opacity MapPolylines, ~8–20% opacity thin strokes, whose additive overdraw creates the Strava-heatmap glow); dedicated libraries exist (DTMHeatmap, JDSwiftHeatMap) but are old Objective-C/abandoned. The critical enabler is caching decoded coordinates locally (SwiftData/files, optionally encoded-polyline or Douglas-Peucker-simplified) because re-running HKWorkoutRouteQuery for hundreds of workouts on every launch is prohibitively slow.
- GPX import/export is solved by CoreGPX (vincentneo/CoreGPX, SPM, full GPX 1.1 schema, iOS 12+, Foundation-only) or GPXKit (mmllr/GPXKit, which adds distance/elevation computation and track simplification); export maps each CLLocation to a trkpt with lat/lon/ele/time (multiple HKWorkoutRoutes should become multiple <trkseg>), and import can either render directly or be written back into HealthKit via HKWorkoutRouteBuilder attached to a saved HKWorkout (requires share/write authorization). Reference implementations: aelptos/GPX and pilif/GpxExport on GitHub.
- The Apple Watch Ultra line's dual-frequency L1+L5 GNSS is market-leading in reviews (the5krunner scored Ultra 3 GPS 90%, exact-match on a measured 2-mile course; strong lock under tree cover, canyons, urban multipath), but there is no developer API to it — apps simply receive the already-fused, smoothed CLLocations via the HealthKit route, so the app inherits Ultra 3 accuracy for free. Some 2025 field reports note occasional distance overestimation (~1.5 km long in dense Korean cities), reinforcing 'trust HKWorkout distance statistic, use route for shape'.
- MapKit has NO public offline-maps API (Apple Maps app offline areas are not exposed to developers; tile caching is transient/LRU only). Offline options are: MKTileOverlay with canReplaceMapContent=true plus a disk cache (merlos/MapCache pod implements LRU offline tile caching for OSM-style {z}/{x}/{y} templates), or switching to MapLibre Native iOS (SPM: maplibre-gl-native-distribution) which has first-class offline packs, vector tiles, and a SwiftUI wrapper (maplibre/swiftui-dsl); free tile sources include OpenFreeMap, Protomaps PMTiles (self-hostable), and MapTiler/Stadia free tiers.
- MapLibre's main draw for this project besides offline is full basemap styling via style JSON — a custom cream/ivory basemap with terracotta accents matching the Anthropic aesthetic is impossible in MapKit (closest MapKit gets is .mapStyle(.standard(elevation:, emphasis: .muted, pointsOfInterest: .excludingAll)) which yields a desaturated minimal look); for a personal single-user app MapKit remains zero-key/zero-cost and needs no tile provider.
- HealthKit privacy plumbing for routes: request read authorization for HKSeriesType.workoutRoute() alongside HKObjectType.workoutType(), add NSHealthShareUsageDescription (and NSHealthUpdateUsageDescription if writing imported GPX); routes recorded by the native Workout app are readable by third-party apps once authorized. Free-provisioning sideload note: HealthKit entitlement works with a free Apple ID, so nothing here requires a paid developer account.

## Specifics
- API: HKSeriesType.workoutRoute() — sample type for route authorization and queries
- API: HKQuery.predicateForObjects(from: workout) — predicate to fetch the route samples belonging to one HKWorkout
- API: HKWorkoutRouteQuery(route:) { query, locations, done, error in ... } — streams [CLLocation] batches (~100/batch) until done == true; wrap in withCheckedThrowingContinuation or AsyncThrowingStream
- Gotcha: one HKWorkout can own multiple HKWorkoutRoute samples — iterate all, export as multiple <trkseg> (pilif/GpxExport issue #1 crash)
- CLLocation fields available per route point: coordinate, timestamp, altitude (barometric-fused), speed (m/s, for pace), course, horizontalAccuracy, verticalAccuracy; ~1 Hz sampling, pre-smoothed by watchOS
- SwiftUI (iOS 17+): Map { MapPolyline(coordinates: coords).stroke(Gradient(colors: [.red, .indigo]), style: StrokeStyle(lineWidth: 5, lineCap: .round, lineJoin: .round)) } — gradient follows the line but stops are evenly spaced, not data-driven
- MapPolyline initializers: MapPolyline(coordinates:), MapPolyline(_ mkPolyline: MKPolyline), MapPolyline(_ route: MKRoute)
- Data-driven gradient: MKGradientPolylineRenderer (iOS 13+) via UIViewRepresentable MKMapView; renderer.setColors([UIColor], locations: [CGFloat]) where locations are cumulative unit-distance fractions 0...1 — compute fraction_i = dist(0..i)/totalDist, color_i = paceOrHRZoneColor(point_i)
- Pure-SwiftUI alternative for zone coloring: chunk route into N short MapPolyline segments each with solid .stroke(zoneColor) — OK to a few thousand segments
- Camera fit: MapCameraPosition.rect(polyline.boundingMapRect) (or .region) with padding to frame the route; minimal basemap via .mapStyle(.standard(emphasis: .muted, pointsOfInterest: .excludingAll))
- Thumbnails: MKMapSnapshotter + MKMapSnapshotter.Options (mapRect/region, size, scale/traitCollection, pointOfInterestFilter = .excludingAll); after snapshot, UIGraphicsImageRenderer + snapshot.point(for: coordinate) to project and stroke the route (e.g. 4pt #D97757 line); cache PNG per workout UUID
- Elevation profile: Swift Charts AreaMark/LineMark with x = cumulative distance (CLLocation.distance(from:)), y = altitude, .interpolationMethod(.catmullRom), linear-gradient foregroundStyle; color-code climb/descent segments by grade
- Elevation gain algorithm: smooth altitude (moving average or Kalman), hysteresis threshold before accumulating ascent — Strava uses ~2 m threshold with barometric data, ~10 m GPS-only
- Workout metadata key: HKMetadataKeyElevationAscended (HKElevationAscended) stored on Watch workouts — direct read of Apple's own ascent number
- Heatmap pattern A: single custom MKOverlay + MKOverlayRenderer drawing all cached polylines in one draw pass (best perf)
- Heatmap pattern B: stack all routes as thin MapPolylines with accent color at 0.08–0.2 opacity; overdraw creates Strava-glow effect
- Heatmap libs (legacy): DTMHeatmap (MKOverlay heatmap, CocoaPods) and jamesdouble/JDSwiftHeatMap (Swift, customizable)
- Perf: cache decoded [CLLocationCoordinate2D] per workout locally (SwiftData or flat binary/encoded-polyline files); optionally Douglas-Peucker simplify for the all-activities heatmap; never re-query HealthKit routes on each launch
- GPX library: CoreGPX (github.com/vincentneo/CoreGPX) — SPM/CocoaPods/Carthage, full GPX 1.1, parse via GPXParser(withURL:)?.parsedData(), Foundation-only, iOS 12+/watchOS 4+
- GPX library alt: mmllr/GPXKit — adds elevation/distance computation and track simplification; also isklikas/iOS-GPX-Framework, anconaesselmann/SwiftGpx
- GPX export mapping: CLLocation → GPXTrackPoint(latitude:longitude:) with .elevation = altitude, .time = timestamp; one <trkseg> per HKWorkoutRoute
- GPX import → HealthKit: build HKWorkout (HKWorkoutBuilder) then HKWorkoutRouteBuilder.insertRouteData([CLLocation]) and finishRoute(workout:metadata:) — requires HealthKit write auth
- Reference GPX exporters: github.com/aelptos/GPX, github.com/pilif/GpxExport, App Store 'WorkoutGPX'
- Ultra 3 GNSS: dual-frequency L1+L5 (GPS/GLONASS/Galileo/QZSS/BeiDou); the5krunner review scored GPS 90%, exact 2.00 mi on measured 2-mi course; no raw GNSS/dev API — accuracy arrives for free through HealthKit route CLLocations
- Known Ultra caveat: 2025 field reports of distance overestimation (~+1.5 km) in dense urban Korea — prefer HKWorkout distance statistics over route-summed distance for the headline number
- Offline: MapKit has no offline API; MKTileOverlay(urlTemplate: "https://tile.openstreetmap.org/{z}/{x}/{y}.png") + canReplaceMapContent = true + merlos/MapCache (LRU disk cache) enables offline raster tiles; respect OSM tile usage policy
- MapLibre stack: SPM package maplibre-gl-native-distribution + maplibre/swiftui-dsl (MapLibreSwiftUI declarative wrapper); MLNOfflineStorage offline packs; custom style JSON enables a cream/ivory + terracotta (#D97757) branded basemap; free tiles via OpenFreeMap, Protomaps PMTiles (self-host), MapTiler/Stadia free tiers
- Auth/plist: read auth for HKSeriesType.workoutRoute() + HKObjectType.workoutType(); NSHealthShareUsageDescription required (NSHealthUpdateUsageDescription if importing GPX into HealthKit); HealthKit entitlement works under free provisioning
- Snapshot dark mode: set MKMapSnapshotter.Options.traitCollection = UITraitCollection(userInterfaceStyle:) to render theme-matching thumbnails

## Recommendations
- Use iOS 17 SwiftUI MapKit as the primary map layer (zero cost, no API keys, no tile provider) with .mapStyle(.standard(emphasis: .muted, pointsOfInterest: .excludingAll)) for the minimal, muted basemap that fits the cream/coral aesthetic; only adopt MapLibre + custom style JSON later if a truly brand-colored (ivory/terracotta) basemap or offline packs become must-haves.
- Build a small RouteStore that, once per workout, runs HKWorkoutRouteQuery, concatenates all route segments, and persists simplified coordinates + per-point speed/altitude locally (SwiftData or binary files keyed by workout UUID) — this single cache powers the detail map, thumbnails, elevation chart, heatmap, and GPX export without repeated slow HealthKit queries.
- For the workout detail map, wrap MKMapView in UIViewRepresentable and use MKGradientPolylineRenderer.setColors(_:locations:) with cumulative-distance fractions to color the route by pace or HR zone (terracotta→deep coral ramp); use plain SwiftUI MapPolyline with a simple gradient stroke everywhere a data-accurate gradient isn't needed.
- Generate list thumbnails with MKMapSnapshotter + Core Graphics route drawing (snapshot.point(for:)), stroked in #D97757 on the muted basemap, rendered once and cached as PNG per workout UUID with a dark-mode variant via Options.traitCollection.
- Implement the personal heatmap as one custom MKOverlayRenderer drawing all cached (Douglas-Peucker-simplified) polylines at low opacity in the accent color — the additive overdraw gives the Strava-glow look without any heatmap library.
- Compute the elevation profile from cached route altitudes with Swift Charts (AreaMark over cumulative distance, catmullRom interpolation) and calculate ascent with a 2 m hysteresis threshold on smoothed barometric altitude, cross-checking against HKMetadataKeyElevationAscended; show HKWorkout's distance statistic as the headline distance, not route-summed distance.
- Add GPX via CoreGPX: export each workout (one <trkseg> per HKWorkoutRoute, trkpt with ele/time) through a share sheet, and support import by parsing GPX to display and optionally writing to HealthKit with HKWorkoutBuilder + HKWorkoutRouteBuilder.
- Always handle multiple HKWorkoutRoute samples per workout and empty-route workouts (indoor); the Ultra 3's dual-frequency GPS needs no configuration — its accuracy flows through automatically.
