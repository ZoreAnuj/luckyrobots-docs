# watchos-live

## Key findings
- A sideloaded/free-provisioned (Personal Team) app CAN include a watchOS companion app: Xcode free provisioning explicitly supports iOS, watchOS and tvOS deployment to your own devices; the watch app installs through the paired iPhone over Wi-Fi. Caveats: the signing profile expires every 7 days (re-run from Xcode weekly or the app stops launching on both devices), a free Apple ID is limited to ~3 simultaneously installed sideloaded apps and 10 App IDs per 7 days, and a paired iOS+watch app can consume two of those slots — developer-forum reports show a second watch app failing to install because 'maximum number of apps for free development profiles' was reached. First launch on the watch requires manually trusting the developer cert on-device.
- HealthKit and App Groups entitlements work on free Personal Team accounts, so the full live-workout stack (HKWorkoutSession + HKLiveWorkoutBuilder) is usable when sideloading; what free accounts cannot use is push notifications, iCloud/CloudKit sync, and App Store/TestFlight distribution.
- The canonical live-tracking architecture on watchOS is: HKWorkoutConfiguration (activityType + locationType) -> HKWorkoutSession(healthStore:configuration:) -> builder = session.associatedWorkoutBuilder() -> builder.dataSource = HKLiveWorkoutDataSource(healthStore:workoutConfiguration:) -> session.prepare() (spin up sensors during a ~3s countdown) -> session.startActivity(with: Date()) + builder.beginCollection(withStart:). Real-time metrics arrive in the HKLiveWorkoutBuilderDelegate callback workoutBuilder(_:didCollectDataOf:), where you read builder.statistics(for: quantityType)?.mostRecentQuantity() — heart rate updates roughly every 1-5 seconds during a session. Session lifecycle (notStarted/prepared/running/paused/stopped/ended) is observed via HKWorkoutSessionDelegate.
- MAJOR 2025 change: since iOS 26/iPadOS 26 (WWDC25 session 322 'Track workouts with HealthKit on iOS and iPadOS'), HKWorkoutSession + HKLiveWorkoutBuilder + HKLiveWorkoutDataSource run natively on iPhone. But the iPhone has no HR sensor and CANNOT pull live heart rate from a paired Apple Watch through this API — it only supports the iPhone's own sensors (GPS, accelerometer/pedometer) plus Bluetooth GATT heart-rate-profile accessories (chest straps, Powerbeats Pro 2). So an iPhone-only custom app still cannot show live wrist HR; live wrist HR requires your own watch app.
- Workout session mirroring (watchOS 10+/iOS 17+) is the purpose-built live watch->iPhone bridge: the watch calls session.startMirroringToCompanionDevice(), the system launches the iPhone app (even in background) and hands it a mirrored HKWorkoutSession via healthStore.workoutSessionMirroringStartHandler; both sides can exchange arbitrary Data with session.sendToRemoteWorkoutSession(data:completion:). This is more reliable for live workout data than WatchConnectivity and also drives iPhone Live Activities.
- WatchConnectivity remains the general-purpose sync channel: sendMessage/sendMessageData for interactive low-latency (requires .reachable counterpart; watch->iPhone wakes the iPhone app in background, but iPhone->watch only reaches the watch app when it is foreground/wrist-up), updateApplicationContext for latest-state-wins background sync (newer dict replaces unsent older one), transferUserInfo for queued FIFO delivery, transferFile for bulk. Best practice: sendMessage for live stats, applicationContext for settings/state, transferUserInfo/File for post-workout payloads.
- You get an enormous amount 'for free' from the built-in Workout app without writing any watch code: every workout is saved as HKWorkout with duration/totals, HKWorkoutRoute GPS series (query via HKWorkoutRouteQuery in batches of CLLocation — enough to draw Strava-style maps), a full heart-rate time series (use HKQuantitySeriesSampleQuery for per-beat-resolution data), active+basal energy, distance, and on Series 6+/watchOS 9+ outdoor runs: runningPower, runningSpeed, runningStrideLength, runningGroundContactTime, runningVerticalOscillation, plus heartRateRecoveryOneMinute auto-saved post-workout, estimatedWorkoutEffortScore (watchOS 11+), vo2Max estimates, elevation-ascended and weather metadata, and workout events/activities for pauses/segments/laps/splits. The limitation is latency: this data syncs to the iPhone Health store after the workout ends (or opportunistically), so it supports history/analysis/maps but NOT a live in-workout iPhone display.
- For custom GPS routes in your own watch app: run CLLocationManager on the watch during the session (kCLLocationAccuracyBest), filter locations by horizontalAccuracy, feed them to HKWorkoutRouteBuilder.insertRouteData(), then finishRoute(with:metadata:) attached to the finished HKWorkout. The watch app needs the WKBackgroundModes 'workout-processing' key (keeps app running with screen off/wrist down) and location usage descriptions.
- Always-on display: since watchOS 8, an app running an active workout session stays frontmost when the wrist drops and keeps updating at 1Hz in the Always-On (luminance-reduced) state. Implement with SwiftUI TimelineView(.periodic/.animation) and the @Environment(\.isLuminanceReduced) flag to dim/redact and drop sub-second timers; seconds-precision timers should degrade to whole-second display. This matches the built-in Workout app behavior on the Ultra's always-on LTPO display.
- Water lock: WKInterfaceDevice.current().enableWaterLock() (watchOS 6.1+, main thread, device waterResistanceRating check; isWaterLockEnabled to query). The system enables water lock automatically when you start an HKWorkoutSession with a swimming/water activity type, so manual calls are only needed for custom water activities.
- Motion sensors on watch: CMMotionManager delivers accelerometer/gyro/magnetometer/deviceMotion up to 100 Hz (low latency, per-sample). For workout-grade high-rate data, CMBatchedSensorManager (watchOS 10, Series 8+/Ultra, requires an active HKWorkoutSession) delivers 800 Hz accelerometer and 200 Hz device-motion in once-per-second batches — ideal for rep counting or stroke/swing detection. Apple Watch Ultra additionally exposes CMWaterSubmersionManager (depth + water temperature). CMPedometer gives live cadence/step data on watch too.
- Apple's official sample code for this exact app is 'Building a workout app for Apple Watch' (the SpeedySloth successor) — HKWorkoutSession + HKLiveWorkoutBuilder + mirroring + SwiftUI; community walkthroughs: BrightDigit's HKLiveWorkoutBuilder tutorial, Sasquatch Studio's 2025 'Building a Workout App for Apple Watch', and createwithswift.com's iOS 26 workout-tracking article.
- Known pitfalls from developer forums: HKLiveWorkoutBuilder sometimes reports only heart rate if the HKLiveWorkoutDataSource isn't attached or types aren't enabled before beginCollection; distance types differ per activity (distanceWalkingRunning vs distanceCycling vs distanceSwimming); mirrored sessions throw 'remote session delegate not set up' if the iPhone-side handler isn't registered early in app launch; free-provisioning watch installs are flaky on first deploy (workaround: launch manually on watch, trust cert, retry).

## Specifics
- HKWorkoutSession(healthStore:configuration:) — watchOS 2+; ALSO iOS 26+ (iPhone-native workout sessions, WWDC25 session 322)
- HKLiveWorkoutBuilder via session.associatedWorkoutBuilder(); delegate callbacks workoutBuilder(_:didCollectDataOf: Set<HKSampleType>) and workoutBuilderDidCollectEvent(_:); read stats via builder.statistics(for:)?.mostRecentQuantity()/averageQuantity()/sumQuantity()
- HKLiveWorkoutDataSource(healthStore:workoutConfiguration:) with enableCollection(for:predicate:) — attach BEFORE beginCollection or you may only get heart rate
- Session lifecycle: prepare() -> startActivity(with:) -> pause()/resume() -> end(); states notStarted/prepared/running/paused/stopped/ended via HKWorkoutSessionDelegate.workoutSession(_:didChangeTo:from:date:)
- Finish flow: builder.endCollection(withEnd:) -> builder.finishWorkout() -> HKWorkoutRouteBuilder.finishRoute(with:metadata:)
- Mirroring APIs (watchOS 10/iOS 17+): session.startMirroringToCompanionDevice(completion:), healthStore.workoutSessionMirroringStartHandler, session.sendToRemoteWorkoutSession(data:completion:) — bidirectional arbitrary Data channel during live workout
- watchOS Info.plist: WKBackgroundModes = ['workout-processing'] (+ location usage keys for route recording)
- Live quantity identifiers: .heartRate, .activeEnergyBurned, .distanceWalkingRunning, .distanceCycling, .distanceSwimming, .swimmingStrokeCount, .runningPower (watts, watchOS 9), .runningSpeed, .runningStrideLength, .runningGroundContactTime, .runningVerticalOscillation, .cyclingPower/.cyclingCadence/.cyclingSpeed (watchOS 10, BT sensors), .stepCount
- Post-workout auto-saved by watch: .heartRateRecoveryOneMinute (watchOS 9), .vo2Max, estimatedWorkoutEffortScore + workoutEffortScore (iOS 18/watchOS 11; query with HKQuery.predicateForWorkoutEffortSamplesRelated(workout:activity:))
- Route reading (iPhone side, no watch app needed): HKSeriesType.workoutRoute() + HKAnchoredObjectQuery with HKQuery.predicateForObjects(from: workout), then HKWorkoutRouteQuery streaming CLLocation batches
- High-res HR history: HKQuantitySeriesSampleQuery (workout HR samples have count>1 encoding finer-grained series); charting: HKStatisticsCollectionQuery with interval
- Running dynamics availability: outdoor runs only, Apple Watch SE/Series 6+ on watchOS 9+ (Ultra 3 fully supported)
- Always-on: workout-session apps stay frontmost and update at 1Hz; SwiftUI TimelineView(PeriodicTimelineSchedule) + @Environment(\.isLuminanceReduced); watchOS 8+
- Water lock: WKInterfaceDevice.current().enableWaterLock() (watchOS 6.1+, main-thread, needs waterResistanceRating .wr50+; Ultra is WR100); isWaterLockEnabled; auto-enabled for swim workout activity types
- Motion: CMMotionManager deviceMotion/accelerometer max 100 Hz; CMBatchedSensorManager (watchOS 10, Series 8+/Ultra, requires active HKWorkoutSession) = 800 Hz accel + 200 Hz deviceMotion in 1 s batches; CMWaterSubmersionManager (Ultra) for depth/water temp; CMPedometer for live cadence
- WatchConnectivity: WCSession.default; sendMessage(_:replyHandler:errorHandler:) interactive (watch->iPhone wakes phone app in background; iPhone->watch needs watch app foreground); updateApplicationContext (latest-state-wins); transferUserInfo (queued FIFO); transferFile (bulk); payloads must be plist types, ~65KB message limit
- iOS 26 iPhone workout sessions: sensors = GPS + accelerometer + Bluetooth GATT Heart Rate Profile accessories ONLY (chest straps, Powerbeats Pro 2); paired Apple Watch is NOT a live HR source for iPhone HKWorkoutSession
- Free provisioning facts: 7-day profile expiry (weekly re-deploy via Xcode); ~3 apps installed simultaneously per free Apple ID; 10 App IDs per 7 days (reuse the same bundle ID); watch app installs via paired iPhone over Wi-Fi; must trust developer cert on both iPhone and watch on first run; allowed entitlements include HealthKit + App Groups; NOT allowed: push notifications, iCloud/CloudKit, App Store distribution
- Apple sample code: 'Building a workout app for Apple Watch' (developer.apple.com, SpeedySloth successor) covers session + builder + mirroring + SwiftUI
- Route building on watch: CLLocationManager(kCLLocationAccuracyBest) during session, filter horizontalAccuracy (e.g. <= 50 m), HKWorkoutRouteBuilder.insertRouteData(_:completion:)
- Built-in Workout app splits/segments: HKWorkout.workoutActivities (HKWorkoutActivity, iOS 16+) and workoutEvents (.pause/.resume/.segment/.lap/.marker); metadata keys HKMetadataKeyElevationAscended, HKMetadataKeyAverageMETs, HKMetadataKeyWeatherTemperature/Humidity, HKMetadataKeyIndoorWorkout

## Recommendations
- Ship a two-tier design: v1 iPhone-only app that reads everything the built-in Workout app records (workouts, HR series, routes via HKWorkoutRouteQuery, running dynamics, effort scores) — zero watch code, full Strava-style maps and RPG XP from completed workouts; v2 adds a custom watch app only if live in-workout UI on your own watch face matters. The free-data path is surprisingly rich on an Ultra 3.
- A watch companion IS feasible with free provisioning, but budget for the friction: re-deploy from Xcode every 7 days on both devices, keep one stable bundle ID to avoid the 10-App-ID/week cap, and expect the paired watch app to eat a second slot of the 3-app limit — keep this the ONLY sideloaded app if possible.
- If you build the watch app, use the modern stack: HKWorkoutSession + associatedWorkoutBuilder + HKLiveWorkoutDataSource, prepare() with a 3 s countdown, WKBackgroundModes=workout-processing, TimelineView + isLuminanceReduced for always-on, and let swim types auto-water-lock. Base it on Apple's 'Building a workout app for Apple Watch' sample.
- For live watch->iPhone stats (big map on the phone while running), prefer workout session mirroring (startMirroringToCompanionDevice + sendToRemoteWorkoutSession) over raw WatchConnectivity; use WatchConnectivity applicationContext only for settings/RPG-state sync and transferFile for post-workout payloads.
- Do NOT plan on the iOS 26 iPhone HKWorkoutSession as a substitute for a watch app: it cannot read live HR from the Apple Watch (Bluetooth-HRM accessories only). Its real value for this project is running the mirrored iPhone side of a watch-initiated session and driving a Live Activity.
- Since free provisioning forbids CloudKit and push, keep all sync local: HealthKit is the shared source of truth between watch and iPhone (both write/read the same store), App Groups + WatchConnectivity for RPG/avatar state; no server needed for a personal app.
- Derive gamification inputs from data the watch already saves automatically: estimatedWorkoutEffortScore, heartRateRecoveryOneMinute, runningPower PRs, elevationAscended metadata, and HR-zone time computed from the HR series — these make good XP formulas without any custom live collection.
- If you later want rep-counting or stroke detection minigames, CMBatchedSensorManager (800 Hz accel during an active session, supported on Ultra 3) is the API to design around — but it requires your own watch app and an active HKWorkoutSession.
