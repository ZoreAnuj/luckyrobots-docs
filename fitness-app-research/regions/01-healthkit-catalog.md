# healthkit-catalog

## Key findings
- HealthKit exposes ~100 HKQuantityTypeIdentifiers, ~60 HKCategoryTypeIdentifiers, 6 characteristic types, plus special sample classes (HKWorkout, HKWorkoutRoute, HKElectrocardiogram, HKHeartbeatSeriesSample, HKAudiogram, HKStateOfMind). A fitness app needs roughly 45-55 of them; everything the Apple Watch Ultra 3 writes automatically is readable with user permission.
- Apple Watch automatically writes (no app code needed): heartRate (every ~4-7 min at rest, per-second in workouts), restingHeartRate, walkingHeartRateAverage, heartRateVariabilitySDNN (periodic + during sleep), heartRateRecoveryOneMinute (post-workout), vo2Max (from outdoor walk/run/hike), activeEnergyBurned, basalEnergyBurned, stepCount, distanceWalkingRunning, flightsClimbed, appleExerciseTime, appleStandTime, respiratoryRate (during sleep), oxygenSaturation, appleSleepingWristTemperature, appleSleepingBreathingDisturbances, sleepAnalysis with stages, timeInDaylight, physicalEffort, and full workout+GPS route samples for outdoor workouts.
- Running dynamics were added in iOS 16 and are auto-captured by Apple Watch during running workouts: runningPower (W), runningSpeed (m/s), runningStrideLength (m), runningGroundContactTime (ms), runningVerticalOscillation (cm). Cycling metrics came in iOS 17: cyclingPower, cyclingCadence, cyclingSpeed, cyclingFunctionalThresholdPower (FTP auto-estimated; power/cadence require paired Bluetooth sensors).
- iOS 17 added physicalEffort (MET-like intensity, kcal/hr/kg, auto-written all day) and timeInDaylight (minutes, from ambient light sensor). iOS 18 added workoutEffortScore and estimatedWorkoutEffortScore (1-10 RPE scale; watch writes the estimate, user/app can write the manual score; linked to a workout via HKWorkoutEffortRelationshipQuery / unified predicateForWorkoutEffortSamplesRelated(workout:activity:)). iOS 18.1 added appleSleepingBreathingDisturbances (sleep-apnea pipeline) with HKAppleSleepingBreathingDisturbancesClassification (notElevated/elevated).
- iOS 26 (released Sept 2025) added no major new fitness quantity identifiers but brought HKLiveWorkoutDataSource to iOS/iPadOS (previously watchOS-only) with out-of-the-box Bluetooth HRM support on iPhone; Apple's new Sleep Score in the Health app has NO developer API, so a recovery/sleep score must be computed in-app from raw components.
- Sleep is a category type: sleepAnalysis with HKCategoryValueSleepAnalysis values inBed, awake, asleepUnspecified, asleepCore, asleepDeep, asleepREM (stages since iOS 16). Watch writes one sample per stage segment; nights must be reconstructed by stitching samples between ~6pm-6pm boundaries and filtering by source to avoid double counting with iPhone.
- GPS routes: HKWorkoutRoute is a series sample linked to an HKWorkout. Read with HKWorkoutRouteQuery (or HKWorkoutRouteQueryDescriptor async), which streams batches of CLLocation (lat/lon/altitude/speed/timestamp/accuracy) — this is everything needed for Strava-style MapKit polyline maps. Locate the route via HKSeriesType.workoutRoute() + HKQuery.predicateForObjects(from: workout). Watch outdoor workout types record routes automatically; writing your own requires HKWorkoutRouteBuilder.
- HKWorkout metadata model: activityType (HKWorkoutActivityType, ~80 cases incl. running, cycling, swimming, HIIT, traditionalStrengthTraining, functionalStrengthTraining, yoga, hiking, stairClimbing), duration, workoutEvents (pause/resume/lap/segment/marker), workoutActivities (multisport sub-activities, iOS 16), and metadata keys (HKMetadataKeyIndoorWorkout, ElevationAscended, AverageMETs, WeatherTemperature, SwimmingLocationType, LapLength). Since iOS 16 totalEnergyBurned/totalDistance are deprecated — read per-workout stats via workout.statistics(for: HKQuantityType) / allStatistics (gives avg/min/max heartRate, sum activeEnergy, sum distance, avg runningPower, etc.).
- Per-second workout heart rate is stored as high-frequency series data: use HKQuantitySeriesSampleQuery to unpack a single HR sample into its underlying per-second values; beat-to-beat intervals (for richer HRV) come from HKHeartbeatSeriesSample via HKHeartbeatSeriesQuery.
- Authorization is per-type and asymmetric: requestAuthorization(toShare:read:) shows one grouped sheet; read-denial is invisible by design — authorizationStatus(for:) only reports WRITE status, and denied-read queries silently return empty results. Use getRequestStatusForAuthorization to know whether the sheet needs showing. Requires HealthKit capability/entitlement + NSHealthShareUsageDescription and NSHealthUpdateUsageDescription in Info.plist. HealthKit IS available to free personal-team provisioning (unlike iCloud/Push), so the sideload plan works.
- Several Apple-computed types are read-only (cannot be written by third-party apps): appleExerciseTime, appleStandTime, appleStandHour, appleWalkingSteadiness, appleSleepingWristTemperature, appleSleepingBreathingDisturbances, walkingHeartRateAverage, heartRateRecoveryOneMinute, atrialFibrillationBurden. Most others (heartRate, vo2Max, bodyMass, all dietary*) are read+write.
- Query architecture for a dashboard app: HKStatisticsCollectionQuery is the workhorse — time-bucketed sums/averages (e.g. daily steps, weekly kcal) with an initialResultsHandler plus a live statisticsUpdateHandler, and it automatically de-duplicates overlapping iPhone+Watch samples (summing raw samples yourself double-counts steps). HKStatisticsQuery for single aggregates; options .cumulativeSum for cumulative types (steps, energy, distance) vs .discreteAverage/.discreteMin/.discreteMax/.mostRecent for discrete types (heartRate, HRV, vo2Max).
- Incremental sync + change tracking: HKAnchoredObjectQuery returns new samples AND HKDeletedObject tombstones since a persisted HKQueryAnchor (serialize via NSKeyedArchiver) — the correct pattern for keeping a local workout/food cache in sync. Modern Swift equivalents: HKSampleQueryDescriptor / HKAnchoredObjectQueryDescriptor with async results(for:) and a long-running .results AsyncSequence.
- Background freshness: HKObserverQuery fires on new data only while the app runs; pairing it with healthStore.enableBackgroundDelivery(for:frequency:) (.immediate/.hourly/.daily/.weekly) wakes the app in background. Requires the com.apple.developer.healthkit.background-delivery entitlement since iOS 15. Hard caps per type regardless of requested frequency: stepCount/distance/energy at most hourly; heartRate/workouts can be effectively immediate; sleepAnalysis roughly on sleep-session end. You must call the completionHandler in the observer callback or iOS throttles/suspends delivery (3 misses = suspended).
- Activity rings are their own API: HKActivitySummary via HKActivitySummaryQuery gives per-day activeEnergyBurned + goal, appleExerciseTime + goal, appleStandHours + goal (and appleMoveTime for the move-time ring mode) — ideal direct fuel for an XP/leveling system and streak mechanics.
- Nutrition is entirely write-side for this app: nothing writes dietary data automatically. Identifiers: dietaryEnergyConsumed (kcal), dietaryProtein/dietaryCarbohydrates/dietaryFatTotal/dietaryFatSaturated/dietaryFiber/dietarySugar (g), dietaryWater (L or mL), dietaryCaffeine (mg), dietarySodium/dietaryPotassium/dietaryCalcium/dietaryIron (mg/g), plus ~25 more micronutrients (vitamins A/B6/B12/C/D/E/K, folate, zinc, magnesium, cholesterol). Group a meal's samples with HKCorrelationTypeIdentifier.food or shared metadata.
- Mobility metrics (iPhone-written automatically while carried): walkingSpeed (m/s), walkingStepLength (m), walkingDoubleSupportPercentage, walkingAsymmetryPercentage, appleWalkingSteadiness, stairAscentSpeed/stairDescentSpeed, sixMinuteWalkTestDistance — low-priority for this app but free recovery/readiness signals.
- Apple Watch Ultra-specific: underwaterDepth (m) and waterTemperature (degC) are auto-written during dives/water sessions (iOS 16+, Ultra only); Ultra 3 also has the full sensor stack (SpO2 restored, wrist temperature, depth gauge, precision dual-frequency GPS for cleaner routes).
- Characteristic types are one-time reads (not samples): dateOfBirth (components), biologicalSex, bloodType, fitzpatrickSkinType, wheelchairUse, activityMoveMode — needed for BMR/calorie math and correct ring interpretation. Body metrics are quantity samples usually manually entered or smart-scale-written: bodyMass (kg), height (m), bodyMassIndex, bodyFatPercentage, leanBodyMass, waistCircumference.
- Recovery-relevant category events the Watch writes: mindfulSession (Breathe/Mindfulness minutes), appleStandHour, highHeartRateEvent/lowHeartRateEvent/irregularHeartRhythmEvent, lowCardioFitnessEvent; iOS 18's HKStateOfMind (valence/labels mood sample, its own HKSample subclass, logged from Mindfulness app) could feed the RPG mood/energy layer.

## Specifics
- Heart quantity IDs: .heartRate (HKUnit count/min, watch auto), .restingHeartRate (count/min, daily auto), .walkingHeartRateAverage (count/min, daily auto, read-only), .heartRateVariabilitySDNN (ms, auto sporadic+sleep), .heartRateRecoveryOneMinute (count/min, iOS 16, auto post-workout, read-only), .vo2Max (ml/kg·min i.e. HKUnit(from: "ml/kg*min"), auto from outdoor cardio), .atrialFibrillationBurden (%, read-only), .peripheralPerfusionIndex (%)
- Energy/activity quantity IDs: .activeEnergyBurned (kcal, watch auto), .basalEnergyBurned (kcal, watch auto), .stepCount (count, iPhone+watch auto), .distanceWalkingRunning (m, auto), .distanceCycling (m, workout-only), .distanceSwimming (m, swim workout), .distanceDownhillSnowSports (m), .distanceWheelchair (m), .pushCount, .flightsClimbed (count, barometer auto), .appleExerciseTime (min, auto, read-only), .appleStandTime (min, auto, read-only), .appleMoveTime (min), .swimmingStrokeCount (count, swim workout auto)
- Running dynamics IDs (iOS 16, all watch auto during running workouts): .runningPower (W), .runningSpeed (m/s), .runningStrideLength (m), .runningGroundContactTime (ms), .runningVerticalOscillation (cm)
- Cycling IDs (iOS 17): .cyclingPower (W), .cyclingCadence (count/min RPM), .cyclingSpeed (m/s), .cyclingFunctionalThresholdPower (W, watch-estimated FTP); power/cadence need paired BT sensors on watchOS; iOS 26 brings HKLiveWorkoutDataSource + BT HRM support to iPhone
- Effort/intensity IDs: .physicalEffort (iOS 17, kcal/hr·kg ~MET, all-day auto), .workoutEffortScore (iOS 18, appleEffortScore unit 1-10, user/app-written), .estimatedWorkoutEffortScore (iOS 18, watch auto); relate/read via HKWorkoutEffortRelationshipQuery and HKQuery.predicateForWorkoutEffortSamplesRelated(workout:activity:); write via healthStore.relateWorkoutEffortSample(_:with:activity:)
- Vitals IDs: .respiratoryRate (count/min, auto during sleep), .oxygenSaturation (%, watch auto periodic+sleep), .bodyTemperature (degC manual), .appleSleepingWristTemperature (degC, iOS 16, auto nightly baseline-relative, read-only), .appleSleepingBreathingDisturbances (iOS 18.1, count/night, read-only, classify with HKAppleSleepingBreathingDisturbancesClassificationForQuantity), .bloodPressureSystolic/.bloodPressureDiastolic (mmHg, manual/BT cuff, correlate via HKCorrelationTypeIdentifier.bloodPressure), .bloodGlucose (mg/dL), .timeInDaylight (min, iOS 17, watch auto)
- Body IDs: .bodyMass (kg), .height (m), .bodyMassIndex (count), .bodyFatPercentage (%), .leanBodyMass (kg), .waistCircumference (m) — manual or smart-scale sourced
- Nutrition IDs (all app-written, unit in parens): .dietaryEnergyConsumed (kcal), .dietaryProtein (g), .dietaryCarbohydrates (g), .dietaryFatTotal (g), .dietaryFatSaturated (g), .dietaryFatMonounsaturated/.dietaryFatPolyunsaturated (g), .dietaryFiber (g), .dietarySugar (g), .dietaryCholesterol (mg), .dietarySodium (mg), .dietaryWater (mL/L), .dietaryCaffeine (mg), plus vitamins/minerals: .dietaryVitaminA/C/D/E/K/B6/B12, .dietaryFolate, .dietaryCalcium, .dietaryIron, .dietaryMagnesium, .dietaryPotassium, .dietaryZinc; group meals with HKCorrelation type .food
- Mobility IDs (iPhone auto): .walkingSpeed (m/s), .walkingStepLength (m), .walkingDoubleSupportPercentage (%), .walkingAsymmetryPercentage (%), .appleWalkingSteadiness (%, read-only), .stairAscentSpeed/.stairDescentSpeed (m/s), .sixMinuteWalkTestDistance (m)
- Ultra/environment IDs: .underwaterDepth (m, iOS 16, Ultra auto-submersion), .waterTemperature (degC, Ultra), .environmentalAudioExposure/.headphoneAudioExposure (dBASPL, auto), .uvExposure (count, manual)
- Category types: .sleepAnalysis (values: inBed=0, asleepUnspecified=1, awake=2, asleepCore=3, asleepDeep=4, asleepREM=5; watch auto with Sleep Focus; use HKCategoryValueSleepAnalysis.allAsleepValues predicate helper), .mindfulSession (watch auto from Mindfulness), .appleStandHour (stood/idle, read-only), .highHeartRateEvent/.lowHeartRateEvent/.irregularHeartRhythmEvent/.lowCardioFitnessEvent (read-only), .toothbrushingEvent/.handwashingEvent
- Characteristics (read once, no samples): dateOfBirthComponents(), biologicalSex(), bloodType(), fitzpatrickSkinType(), wheelchairUse(), activityMoveMode() — throw if unset
- HKWorkout: read via HKObjectType.workoutType() + HKSampleQuery/anchored query; fields: workoutActivityType, duration, workoutEvents ([HKWorkoutEvent] .pause/.resume/.lap/.segment/.marker), workoutActivities ([HKWorkoutActivity] for multisport iOS 16+), sourceRevision (identifies Watch vs 3rd-party), device
- Per-workout stats (iOS 16+ replacement for deprecated totalEnergyBurned/totalDistance): workout.statistics(for: HKQuantityType(.heartRate))?.averageQuantity()/minimumQuantity()/maximumQuantity(), .sumQuantity() for activeEnergyBurned/distanceWalkingRunning/runningPower etc.; workout.allStatistics dictionary
- Useful HKMetadataKey constants on workouts: HKMetadataKeyIndoorWorkout, ElevationAscended, ElevationDescended, AverageMETs, WeatherTemperature, WeatherHumidity, SwimmingLocationType, LapLength, TimeZone; sample-level: HKMetadataKeyHeartRateMotionContext (sedentary/active), HKMetadataKeySyncIdentifier/SyncVersion (upsert semantics for your own writes)
- Route reading recipe: 1) HKAnchoredObjectQuery on HKSeriesType.workoutRoute() with HKQuery.predicateForObjects(from: workout) to get the HKWorkoutRoute sample; 2) HKWorkoutRouteQuery(route:) streams [CLLocation] in batches until done flag; each CLLocation has coordinate, altitude, speed, course, horizontalAccuracy, timestamp — render as MKPolyline; Ultra 3 dual-frequency GPS yields clean traces
- High-frequency series: HKQuantitySeriesSampleQuery unpacks per-second workout heart rate stored inside one HKQuantitySample; HKHeartbeatSeriesQuery over HKSeriesType.heartbeat() yields beat-to-beat intervals (timeSinceSeriesStart + precededByGap) for custom RMSSD-style HRV
- Authorization: healthStore.requestAuthorization(toShare: Set<HKSampleType>, read: Set<HKObjectType>) async; HKHealthStore.isHealthDataAvailable() gate; authorizationStatus(for:) reflects WRITE only (.notDetermined/.sharingDenied/.sharingAuthorized); getRequestStatusForAuthorization(toShare:read:) returns .shouldRequest/.unnecessary; denied read = silent empty results (privacy by design); characteristics are read-only auth
- Entitlements/plist: com.apple.developer.healthkit (+ background-delivery sub-entitlement array), NSHealthShareUsageDescription + NSHealthUpdateUsageDescription required or crash on request; HealthKit capability works under free personal-team provisioning (Xcode sideload OK); HealthKit data itself persists across the 7-day profile expiry/reinstall since it lives in the system Health store — but HKQueryAnchor state lives in your app container
- Background delivery: healthStore.enableBackgroundDelivery(for: type, frequency: .immediate/.hourly/.daily/.weekly); per-type floors regardless of request — stepCount/distanceWalkingRunning/activeEnergyBurned max hourly; heartRate/workout/sleepAnalysis can be near-immediate; observer's completionHandler MUST be called or iOS suspends delivery after 3 misses; real-world watchOS 26 reports show throttling to ~hourly on some devices — design UI to also refresh on foreground
- Observer pattern: HKObserverQuery(sampleType:predicate:updateHandler:) fires with no payload — on wake, run an HKAnchoredObjectQuery with persisted anchor to fetch the delta (new samples + HKDeletedObject list); anchor serialization: try NSKeyedArchiver.archivedData(withRootObject: anchor, requiringSecureCoding: true)
- Statistics: HKStatisticsQuery(quantityType:quantitySamplePredicate:options:) options .cumulativeSum/.discreteAverage/.discreteMin/.discreteMax/.mostRecent/.separateBySource; cumulative types (steps, energy, distance) reject discrete options and vice versa; built-in multi-source dedup means NEVER sum raw step samples manually
- Charts fuel: HKStatisticsCollectionQuery(quantityType:quantitySamplePredicate:options:anchorDate:intervalComponents:) e.g. anchorDate = startOfDay, interval = DateComponents(day: 1); enumerateStatistics(from:to:); statisticsUpdateHandler gives live updates while app runs; Swift async alternative: HKStatisticsCollectionQueryDescriptor
- Modern async API (iOS 15.4+): HKSampleQueryDescriptor(predicates: [.workout(...)], sortDescriptors:), HKAnchoredObjectQueryDescriptor(predicates:anchor:).results(for:) one-shot or .results(for:) AsyncSequence for continuous monitoring; typed predicates HKSamplePredicate.quantitySample(type:predicate:)
- Activity rings: HKActivitySummaryQuery with predicate from HKQuery.predicate(forActivitySummariesBetweenStart:end:) using DateComponents WITH calendar set; HKActivitySummary fields: activeEnergyBurned/Goal, appleExerciseTime/Goal, appleStandHours/Goal, appleMoveTime/Goal, activityMoveMode; also dateComponents(for:) — direct fuel for XP: e.g. XP = kcal + 10*exerciseMin + ringClosureBonus
- Units cheat sheet: HKUnit.count(), .count().unitDivided(by: .minute()) for bpm, .kilocalorie(), .meter(), .meterUnit(with: .kilo), .secondUnit(with: .milli) for HRV/GCT, .percent() (0-1 scale — multiply by 100 for display), .degreeCelsius(), .watt(), .literUnit(with: .milli), HKUnit(from: "ml/kg*min") for VO2max, HKUnit(from: "kcal/hr·kg") for physicalEffort, .appleEffortScore() for effort (iOS 18)
- Sleep reconstruction algorithm: query sleepAnalysis samples in window (previousDay 18:00 → today 18:00), filter to sourceRevision.source.bundleIdentifier prefix "com.apple.health" (watch) to skip 3rd-party duplicates, group into sessions by <1hr gaps, sum per-stage durations, compute efficiency = asleep/inBed; deep+REM proportions feed recovery score
- Recovery score inputs all auto-available on Ultra 3: overnight HRV SDNN samples (predicate on sleep window), restingHeartRate vs 30-day baseline, respiratoryRate deviation, appleSleepingWristTemperature deviation (already baseline-relative), sleep stage distribution, appleSleepingBreathingDisturbances, previous-day physicalEffort/workoutEffortScore for training-load balance
- HKWorkoutActivityType relevant cases: .running, .walking, .hiking, .cycling, .swimming(+HKMetadataKeySwimmingLocationType pool/openWater), .traditionalStrengthTraining, .functionalStrengthTraining, .highIntensityIntervalTraining, .yoga, .pilates, .coreTraining, .elliptical, .rowing, .stairClimbing, .jumpRope, .kickboxing, .soccer, .basketball, .tennis, .crossCountrySkiing, .downhillSkiing, .snowboarding, .surfingSports, .paddleSports, .cooldown, .mindAndBody, .other (~80 total)
- State of mind (iOS 18): HKStateOfMind sample class (not category) with kind (.momentaryEmotion/.dailyMood), valence (-1..1), labels ([.happy, .stressed, ...]), associations ([.fitness, .health]); readable if user logs mood in Mindfulness — optional avatar-mood input

## Recommendations
- Request read authorization once, up front, for a curated set (~45 types across heart, energy, activity, running/cycling dynamics, sleep, vitals, body, workouts+routes+activitySummary) and write access only for dietary*, bodyMass, workouts, and workoutEffortScore; gate the request behind getRequestStatusForAuthorization and treat empty query results as possibly-denied, never error.
- Build every chart and daily stat on HKStatisticsCollectionQuery (day-bucketed, anchored at startOfDay) — it de-duplicates overlapping iPhone+Watch samples for free; never sum raw stepCount/energy samples.
- Sync workouts and meals with persisted-anchor HKAnchoredObjectQueries (handles deletions via HKDeletedObject); layer HKObserverQuery + enableBackgroundDelivery(.immediate) for workouts/heartRate and accept the hourly floor for steps/energy; always call the observer completionHandler and refresh on app foreground as fallback since real-world background delivery throttles.
- For Strava-like maps: fetch route with HKSeriesType.workoutRoute() + HKWorkoutRouteQuery streaming CLLocations, render MKPolyline over MapKit; read per-workout metrics via workout.statistics(for:) (not the deprecated totals) and pull per-second HR with HKQuantitySeriesSampleQuery for in-workout charts.
- Nutrition: your app is the writer — log meals as dietaryEnergyConsumed + macro samples (optionally an HKCorrelation .food per meal) with HKMetadataKeySyncIdentifier so edits upsert cleanly; calories in vs out = dietaryEnergyConsumed vs activeEnergyBurned+basalEnergyBurned.
- Compute recovery in-app (Apple's iOS 26 Sleep Score has no API): blend overnight HRV SDNN, restingHR delta vs baseline, respiratoryRate delta, appleSleepingWristTemperature deviation, sleep-stage distribution, and breathing disturbances — every input is auto-written by the Ultra 3.
- Drive the RPG/XP layer from HKActivitySummary (ring closure, goals), appleExerciseTime, activeEnergyBurned, workout count/streaks, and iOS 18 workoutEffortScore (let the user tap an RPE 1-10 after workouts and write it back, relating it via relateWorkoutEffortSample); this keeps all gamification derivable from HealthKit alone with no separate tracking DB.
- Free provisioning fully supports the HealthKit entitlement (including background delivery); persist HKQueryAnchors and any XP/level state somewhere durable (e.g. App Group or file you can re-import) since the 7-day profile expiry may force reinstalls while the Health store itself keeps all raw data.
